## The helpful vote

Every documentation page ends with "Was this page helpful?". It is a real
`<form method="post">`, so it works with JavaScript disabled — a script upgrades it to
submit in the background and swap in the thank-you state without a page load.

Turn it off per page with `showFeedback: false` in frontmatter, or site-wide in
`src/data/pageTools.json`.

## Where the vote goes

The default `action` posts to the site itself, which
[CloudCannon Forms](https://cloudcannon.com/documentation/host/forms/) captures once the site
is connected to an Inbox — see [Setting up CloudCannon Forms](#setting-up-cloudcannon-forms)
below. Until then, a vote on a CloudCannon-hosted site has nowhere to go.

To send it somewhere else, change one field:

<CodeTabs
  tabs={[
    {
      "label": "CloudCannon",
      "language": "json",
      "code": "{\n  \"feedback\": {\n    \"enabled\": true,\n    \"action\": \"/\"\n  }\n}"
    },
    {
      "label": "Formspree",
      "language": "json",
      "code": "{\n  \"feedback\": {\n    \"enabled\": true,\n    \"action\": \"https://formspree.io/f/YOUR_ID\"\n  }\n}"
    },
    {
      "label": "Netlify",
      "language": "json",
      "code": "{\n  \"feedback\": {\n    \"enabled\": true,\n    \"action\": \"/\"\n  }\n}\n\n// Netlify needs the form to declare itself; the block already\n// posts a `form-name` field, so add data-netlify=\"true\" in\n// navigation/page-feedback/PageFeedback.astro."
    },
    {
      "label": "Your own",
      "language": "json",
      "code": "{\n  \"feedback\": {\n    \"enabled\": true,\n    \"action\": \"https://api.acme.com/docs-feedback\"\n  }\n}"
    }
  ]}
/>

The payload is the same in every case — three fields, posted as `multipart/form-data`:

<ParamList
  params={[
    {
      "name": "form-name",
      "type": "string",
      "required": true,
      "description": "Always `page-feedback`, so one endpoint can serve several forms."
    },
    {
      "name": "page",
      "type": "string",
      "required": true,
      "description": "The path of the page that was voted on, e.g. `/theming/`."
    },
    {
      "name": "vote",
      "type": "string",
      "required": true,
      "description": "`yes` or `no`."
    }
  ]}
/>

<Alert
  variant="warning"
  title="A cross-origin endpoint needs CORS"
  text="The upgraded submit uses `fetch`, so an endpoint on another domain must send `Access-Control-Allow-Origin`. Without it the vote is silently dropped — deliberately: a reader who clicked Yes should never be shown an error."
/>

CloudCannon app, and no code.

A form with no `inbox_key` field goes to the site's default Inbox, which is how the helpful
vote works without any change. To send a particular form to a different Inbox, add a hidden
field named `inbox_key` whose value is that Inbox's key. CloudCannon's guides cover the details:
[creating an Inbox](https://cloudcannon.com/documentation/developer-articles/creating-an-inbox-to-receive-your-forms/)
and [connecting a site to one](https://cloudcannon.com/documentation/articles/connecting-your-site-to-an-inbox/).

To filter spam, set the form's `honeypotName` to `_gotcha`. That adds a field people never
see; CloudCannon discards any submission where a bot filled it in. For more protection, add
a CAPTCHA provider in the Inbox's settings.

<Alert
  variant="note"
  title="Inboxes have a monthly limit"
  text="Each Inbox accepts 2,250 submissions a month. A busy docs site with the helpful vote on every page can reach that — give the vote its own Inbox so it can't crowd out a contact form."
/>

## Any other form

Forms are built from the same blocks as the rest of the site, and can be dropped into a
documentation page. The default `action` is again the site itself, so a CloudCannon-hosted
site with a linked Inbox collects submissions with no backend.

<Form
  action="./"
  formBlocks={[
    {
      "_component": "building-blocks/forms/input",
      "label": "Your email",
      "name": "email",
      "type": "email",
      "placeholder": "you@company.com",
      "required": true
    },
    {
      "_component": "building-blocks/forms/input",
      "label": "Which page?",
      "name": "page",
      "type": "text",
      "placeholder": "/installation/",
      "required": true
    },
    {
      "_component": "building-blocks/forms/textarea",
      "label": "What's missing?",
      "name": "message",
      "rows": 4,
      "required": true
    },
    {
      "_component": "building-blocks/forms/hidden",
      "name": "form-name",
      "value": "docs-gap"
    },
    {
      "_component": "building-blocks/forms/submit",
      "text": "Send",
      "variant": "primary",
      "size": "md"
    }
  ]}
/>

<Alert
  variant="tip"
  title="Validation is the browser's, with better messages"
  text="Fields marked `required` are validated natively; a script replaces the browser's tooltip with an inline message under each field, and focuses the first one that failed."
/>
