## Tokens

Colour, spacing, radius, type and motion are CSS custom properties in three tiers: primitives
in `src/styles/variables/`, semantic tokens in `src/styles/themes/`, and component-local
properties on a component's own root. Components consume the semantic tier only, so a
rebrand is a token change rather than a component change.

```css title="src/styles/themes/_light.css"
[data-theme="light"] {
  --color-accent: var(--teal-700);
  --color-text: var(--black);
  --color-bg: var(--white);
  --color-border: var(--gray-200);
}
```

  text="An unresolved `var()` is invalid at computed-value time, so the property silently inherits — no error anywhere. Run `npm run lint:css-vars -- --list` to print every declared token; `npm run check` fails on an unresolved one."

## The accent

The accent is the interactive colour — links, active sidebar item, focus rings, the marker on
an annotated line, the brand tile in the header. It is deliberately not the button colour:
primary buttons stay ink on paper, so changing the accent never turns the page into a wall of
one hue.

This template ships teal: `--teal-700` on light, `--teal-300` on dark. The dark end of a ramp
is the calmer step for a dark page — a fully saturated accent vibrates against near-black.
Swap both, and `--color-accent-surface` / `--color-accent-border` with them, and every accent
on the site follows.

## Typography

One sans for interface and prose, one mono for code and labels, both registered in
`site-fonts.mjs` — the only place to change them.

```js title="site-fonts.mjs"
export const siteFonts = [
  { name: "Instrument Sans", cssVariable: "--font-body", weights: ["400 700"] },
  { name: "JetBrains Mono", cssVariable: "--font-mono", weights: ["400 600"] },
];
```

Sizes are a fixed scale: headings step 42 / 24 / 18, body sits at 16 with a 1.72 line height
for long reads.

## Dark mode

The mode is applied as `data-theme` on the root element before first paint, so there is no
flash. Try the toggle in the header — nothing here is a screenshot.

Three things decide it, in order:

<ParamList
  params={[

    { name: "defaultTheme", type: '"dark" | "light" | "system"', defaultValue: '"dark"', description: "The site's own default, set in `src/data/docsSite.json`. This template ships dark." },
    { name: "The operating system", type: "prefers-color-scheme", description: "Consulted only when `defaultTheme` is `system`." },
  ]}
/>

<Alert
  variant="note"
  title="A dark default stays dark"
  text="With `defaultTheme: dark`, a reader whose operating system is set to light still gets the dark site until they use the toggle. Set it to `system` if you would rather follow them."
/>

Hiding the toggle (`themeToggle: false`) doesn't change any of this — the scheme is still
resolved, the reader just can't change it.

Code blocks stay dark in both themes on purpose: a sample that inverts with the page re-reads
as a different snippet, and syntax colours are tuned for one ground.
