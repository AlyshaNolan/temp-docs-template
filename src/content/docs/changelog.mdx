Releases live in `src/content/changelog/` — one Markdown file each, holding a version, a date, an optional free-text summary and its tagged lines. This page renders the whole collection, so shipping a release is adding a file rather than editing this page.

The summary sits between the version heading and the list — use it for what a release is about, or for an upgrade note. Leave it out and the release goes straight from its heading to its lines.

The same releases are published as an RSS feed at [`/changelog.xml`](/changelog.xml), so readers can subscribe to them. The feed is built from the collection too, so it needs no upkeep.

An entry tagged `Breaking` is color-coded here. Nothing else happens automatically — if the change affects a reference page, consider adding an `Alert` there too.
