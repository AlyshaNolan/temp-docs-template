## Frontmatter

Only `title` is required. `group` and `order` place the page in the sidebar; omit `group` and
the page still builds and is searchable — it just doesn't appear in the nav.

| Key            | Type    | Default | Effect                                             |
| -------------- | ------- | ------- | -------------------------------------------------- |
| `title`        | string  | —       | Page heading, browser title, search result         |
| `description`  | string  | —       | The lede under the title, and the meta description |
| `group`        | string  | —       | Sidebar group. No group means no sidebar entry     |
| `order`        | number  | `0`     | Position within the group                          |
| `updated`      | date    | —       | Shown in the meta line under the title             |
| `showToc`      | boolean | `true`  | On-this-page rail                                  |
| `showFeedback` | boolean | `true`  | The helpful vote at the foot of the page           |
| `showPager`    | boolean | `true`  | Previous/next links                                |

## Callouts

Four kinds. Use them for things a reader would otherwise learn the hard way.

<Alert variant="note" title="Note" text="Context that helps, but isn't required to succeed." />
<Alert variant="tip" title="Tip" text="A shortcut once the reader knows the basics." />
<Alert variant="warning" title="Warning" text="Something that will surprise them if they skip it." />
<Alert variant="danger" title="Danger" text="Data loss, irreversible actions, breaking changes." />

```mdx title="callout.mdx"
<Alert
  variant="warning"
  title="Rotating a key revokes the old one"
  text="Existing clients fail on the next request. Deploy the new key before rotating."
/>
```

## Diffs

`CodeDiff` marks changed lines with `+`, `-` and `~` at the start of the line. The
markers are stripped before highlighting, so the sample keeps its own language
colours instead of going flat the way a `diff` fence does — and the copy button
hands back the code without them.

<CodeDiff
  filename="docsmith.config.js"
  language="js"
  code={diffSample}
/>

A line of real code that begins with `+`, `-` or `~` — a YAML list item, say — is
read as a marker. Use a plain code block for those.

## File trees

`FileTree` draws the connectors from an indented list of paths, so the tree stays
editable as text. Any consistent indent unit works, and a path can carry the same
`+` / `-` / `~` marker as a diff.

<FileTree
  title="Project structure"
  paths={treeSample}
/>

## Language tabs

Use `CodeTabs` for one sample in several languages. The reader's choice is remembered
site-wide, so a Python developer stays in Python across every page.

<CodeTabs
  tabs={[

  ]}

## Code annotations

Notes sit under the block rather than in comments, so the snippet stays copy-paste clean.
Each note names the line it marks.

<CodeAnnotations
  filename="docsmith.config.js"
  language="js"
  notes={[
    { line: 2, text: "Builds the index at compile time and ships it with the site — no search service, no API key." },
    { line: 4, text: "Point a group at a directory and every page in it appears, ordered by frontmatter." },
  ]}
  code={annotatedSample}
/>

## Tables

Markdown tables get a bordered panel and horizontal scroll on narrow screens.

| Event          | Retries | Payload            |
| -------------- | ------- | ------------------ |
| `invoice.paid` | 5       | Invoice object     |
| `user.created` | 3       | User object        |
| `plan.changed` | 3       | Subscription delta |

## Cross-links

Link by URL — `[Configuration](/configuration/)`. `npm run lint:links` fails the build on an
internal link that points at no page, so a renamed page can't quietly rot.
